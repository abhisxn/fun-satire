Touch Tap-to-Spawn — Decision Gate

PR2 Task 3 · Multi-Subject Targeting. Pick A or B before implementation proceeds.

A Tap → spawn at center

Tapping a subject card immediately spawns the subject at the canvas center. Single tap, single action, no intermediate state.

spawn point (fixed)
  • + Simplest to implement; one event handler, no mode state to track.
  • + Zero ambiguity on touch devices — no risk of the "next tap" landing on the wrong target (HUD button, another card, etc.).
  • + Matches existing desktop click-to-spawn-at-cursor pattern if center is treated as touch's cursor-equivalent.
  • − User has no control over placement; may need to drag the subject afterward if center is occupied or undesired.
  • − Multiple taps in a row stack subjects at the same point, requiring the physics separation system to resolve overlap.
B Tap → placement mode → tap canvas

Tapping a card arms "placement mode" (card highlights, cursor/HUD shows a hint). The next tap on the canvas spawns the subject at that exact point.

② tap canvas → spawn here
① tap card (armed)
  • + Precise placement — user chooses exactly where the subject appears, same as a future drag-and-drop flow.
  • + Scales naturally to placing multiple subjects of different types in sequence.
  • − Requires a mode/state machine addition ("armed" state, cancel-on-outside-tap or cancel-on-second-card-tap, visual affordance for "what happens next").
  • − Ambiguous edge cases: what if the user taps another card while armed? Taps a HUD control? Never taps the canvas at all?
  • − Two-step interactions are less discoverable without an explicit instructional hint, especially on first use.
